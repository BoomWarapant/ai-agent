# crd-bot — คู่มือติดตั้งสำหรับทีมทดลองใช้

crd-bot เป็นผู้ช่วย AI สำหรับทีม CRD ที่ทำงานบน Rakazo v0.1.6 โดยติดตั้งระบบแยกบนเครื่อง Windows ของผู้ทดลองแต่ละคนครับ

**สถานะ: ชุดทดลองแบบติดตั้งทีละขั้น ยังไม่ใช่โปรแกรมติดตั้งคลิกเดียวครับ** ระบบบนเครื่องต้นแบบผ่านการใช้งานแล้ว แต่ยังไม่ได้ทดสอบติดตั้งตั้งแต่ต้นบนเครื่องใหม่ครบทุกขั้นครับ

## ก่อนส่งให้ทีม

ใช้ branch [`feat/research-bots`](https://github.com/BoomWarapant/ai-agent/tree/feat/research-bots) สำหรับชุดทดลองนี้ครับ อย่าดาวน์โหลด default branch โดยไม่ได้ตรวจว่ามีการแก้ไขล่าสุดแล้วครับ

| สิ่งที่ได้รับจาก GitHub | ข้อจำกัด |
|---|---|
| สคริปต์ติดตั้ง Rakazo, Docker Engine ใน WSL, ฟอนต์ไทย และ web tools | ต้องดาวน์โหลด dependencies และ Docker images ระหว่างติดตั้งครับ |
| launcher เปิดหน้าต่างแชต | ต้องติดตั้งบริการและสร้างบัญชีก่อนครับ |
| icon หุ่นยนต์แมว, avatar patches และกติกา swift | ยังไม่ได้ติดตั้ง branding และสร้าง neo/swift อัตโนมัติครับ |
| patch สำหรับลิงก์บทความและวันที่เผยแพร่ | ต้องทำขั้นตอนติดตั้ง patch ด้านล่างครับ |
| เอกสาร Research Bots | เป็นชุดทดลองอีกส่วน ไม่จำเป็นต่อการทดลองแชตพื้นฐานครับ |

GitHub ไม่มีบัญชีโมเดล, API key, `.env` ของเครื่องต้นแบบ, ประวัติแชต, เอกสารโครงการ หรือฐานข้อมูลผู้ใช้ครับ ผู้ทดลองต้องสร้างบัญชีและเชื่อมโมเดลที่ได้รับอนุญาตของตนเองครับ

## 1. เตรียมเครื่อง

- ใช้ Windows 11, Microsoft Edge, Git for Windows และสิทธิ์ Administrator สำหรับติดตั้ง WSL ครับ
- ต้องมี WSL2 ชื่อ `Ubuntu-24.04` และเปิดใช้ systemd ครับ
- ชุดนี้ใช้ Docker Engine ภายใน WSL ตามสคริปต์ของโครงการครับ หากมี Docker Desktop หรือระบบ Docker เดิม ให้ผู้ดูแลตรวจความเข้ากันได้ก่อนครับ
- ต้องมีอินเทอร์เน็ตเข้าถึง GitHub, container registry และผู้ให้บริการโมเดลครับ
- ให้รันเครื่องมือตรวจเครื่องก่อน โดยค่าจัดสรร WSL ในคู่มือเดิมเป็นค่าของเครื่องต้นแบบ ไม่ใช่สเปกขั้นต่ำที่รับรองสำหรับทุกเครื่องครับ

ตรวจ WSL ใน PowerShell ครับ

```powershell
wsl --status
wsl --list --verbose
```

ถ้ายังไม่มี Ubuntu ให้เปิด PowerShell แบบ Administrator แล้วติดตั้งครับ

```powershell
wsl --install -d Ubuntu-24.04
```

ทำตามข้อความบนหน้าจอ รวมถึง restart หากระบบร้องขอ และสร้างผู้ใช้ Ubuntu ให้เสร็จก่อนทำขั้นถัดไปครับ หากเครื่องมี WSL ใช้งานอยู่แล้ว ไม่ต้องติดตั้งทับครับ

## 2. ดาวน์โหลดชุดทดลอง

วิธีแนะนำคือ clone ด้วย Git เพื่อรักษารูปแบบบรรทัดของสคริปต์ครับ รันใน PowerShell ปกติครับ

```powershell
Set-Location $env:USERPROFILE
git clone --branch feat/research-bots --single-branch https://github.com/BoomWarapant/ai-agent.git
Set-Location "$env:USERPROFILE\ai-agent"
git log -1 --oneline
powershell -NoProfile -ExecutionPolicy Bypass -File ".\rakazo\scripts\windows\check-machine.ps1"
```

ถ้ามีโฟลเดอร์ `ai-agent` อยู่แล้ว ให้ใช้โฟลเดอร์ใหม่หรือให้ผู้ดูแลตรวจงานค้างก่อนอัปเดตครับ อย่าเขียนทับชุดที่ใช้งานอยู่ครับ

วิธี Download ZIP: เปิด branch ด้านบน เลือก **Code → Download ZIP** แล้วแตกไฟล์ก่อนครับ ชื่อโฟลเดอร์อาจเป็น `ai-agent-feat-research-bots` ให้ปรับ path ทุกคำสั่งให้ตรงกับตำแหน่งที่แตกไฟล์ครับ ถ้า repository จำกัดสิทธิ์ ต้องให้ผู้ดูแลเพิ่มสิทธิ์ GitHub ก่อนครับ

## 3. ติดตั้งระบบพื้นฐาน

ทำตาม [INSTALL ขั้น 1–6](rakazo/docs/INSTALL.md) ทีละขั้น และหยุดเมื่อมี `[FAIL]` ครับ ลำดับคือปรับทรัพยากร WSL ตามเครื่อง → ติดตั้ง Docker → สร้าง user `rakazo` → ติดตั้ง Rakazo → ตั้งกฎ LAN → ตรวจบริการครับ

คู่มือ INSTALL มีทั้ง PowerShell และ Bash ครับ บล็อก Bash ต้องรันใน WSL ด้วย user ที่หัวข้อระบุ และตั้ง `$REPO` ในแต่ละหน้าต่างตามขั้น 0 ก่อนครับ

ขั้นติดตั้ง Rakazo ให้ใช้คำสั่งนี้ใน WSL ด้วย user `rakazo` ครับ

```bash
bash "$REPO/scripts/wsl/30-install-rakazo.sh" --base-profile
```

`--base-profile` หมายถึงชุดพื้นฐานสำหรับเครื่องใหม่ครับ ห้ามใช้แทนการย้ายระบบต้นแบบที่มี custom images หรือ Memory Hub อยู่แล้วครับ

**ผ่านขั้นนี้เมื่อ** สคริปต์ verify ไม่มี `[FAIL]` และเปิด [หน้าแชตในเครื่อง](http://127.0.0.1:5173) ได้ครับ การเปิดหน้าเว็บได้อย่างเดียวยังไม่ถือว่าบอทตอบได้ ต้องทำขั้นเชื่อมโมเดลด้วยครับ

## 4. เพิ่มความสามารถอ่านบทความและวันที่

ให้ผู้ดูแลทำขั้นนี้ใน WSL ด้วย user `rakazo` หลังติดตั้งระบบพื้นฐานเสร็จครับ `$REPO` ต้องชี้โฟลเดอร์ `rakazo` ในชุดที่ดาวน์โหลดครับ

```bash
cd /home/rakazo/rakazo
patch --dry-run -p1 -d hotfix < "$REPO/scripts/wsl/web-article-evidence.patch"
```

ถ้า dry-run ผ่าน ให้สำรองไฟล์แล้วติดตั้ง patch ครับ

```bash
cp -n hotfix/keyless-http-web.ts hotfix/keyless-http-web.ts.before-article-evidence
patch -p1 -d hotfix < "$REPO/scripts/wsl/web-article-evidence.patch"
docker compose --env-file .env -f docker-compose.images.yml -f docker-compose.override.yml restart api worker
```

หากแจ้งว่า patch ถูกติดตั้งแล้ว, reversed patch หรือ context ไม่ตรง ให้หยุดและให้ผู้ดูแลตรวจเวอร์ชันครับ อย่าฝืนติดตั้งซ้ำครับ patch นี้ทำให้ web_fetch คืนลิงก์บทความและ metadata วันที่ โดยแยก `datePublished` ออกจาก `dateModified` ครับ

## 5. สร้างบัญชี เชื่อมโมเดล และตั้ง neo/swift

1. เปิด [http://127.0.0.1:5173](http://127.0.0.1:5173) แล้วสร้างบัญชีเจ้าของระบบตาม [BOT-SETUP](rakazo/docs/BOT-SETUP.md) ครับ
2. เชื่อมผู้ให้บริการโมเดลในหน้าตั้งค่าของระบบด้วยบัญชีที่องค์กรอนุญาต และทดสอบบอทตอบคำถามสั้น ๆ ก่อนครับ ค่าใช้จ่ายและข้อจำกัดขึ้นอยู่กับ provider และบัญชี ไม่ได้รวมอยู่ใน repository ครับ
3. สร้างบอทชื่อ `neo` และ `swift` โดยให้ทั้งคู่ใช้โมเดลที่เชื่อมไว้ครับ ใช้กติกาบอทเริ่มต้นใน BOT-SETUP สำหรับ neo และเพิ่มบทบาทประสานงานให้ค้นข่าวผ่าน swift ครับ ชุดนี้ยังไม่มีไฟล์ export กติกา neo ฉบับเต็มจากเครื่องต้นแบบครับ
4. คัดลอก [กติกา swift](rakazo/bots/swift/instructions.txt) ลงใน Instructions ของ swift ครับ **เปลี่ยน neo ID ที่อยู่ในไฟล์เป็น ID ของ neo บนเครื่องใหม่** ก่อนใช้ เพราะ ID ในไฟล์เป็นของเครื่องต้นแบบครับ ให้ผู้ดูแลตรวจ ID จากระบบ ไม่ใช้ค่าเดิมหรือเดาค่าครับ
5. ตรวจว่าบอทค้นผ่าน `web_search` และอ่านผ่าน `web_fetch` ได้ครับ การค้นข่าวใช้ web tools ในตัว ไม่จำเป็นต้องมี search MCP แต่ Memory Hub และ Google Drive เป็นการเชื่อมต่อแยกที่ต้องตั้งค่าเพิ่มเติมครับ

เริ่มด้วยข้อมูลทดสอบก่อนครับ อย่าคัดลอก token, session หรือฐานข้อมูลจากเครื่องต้นแบบมาแจกทีมครับ

## 6. สร้าง Shortcut และเปิดใช้งาน

รันใน PowerShell จากโฟลเดอร์ repository ครับ

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\rakazo\scripts\windows\create-shortcut.ps1"
```

สคริปต์ปัจจุบันสร้าง Shortcut ชื่อ **Rakazo** ครับ ดับเบิลคลิกแล้ว launcher จะเปิดบริการและรอเว็บพร้อมก่อนเปิด Edge app window ครับ ต้องเก็บโฟลเดอร์ repository ไว้ที่เดิม หรือรันสร้าง Shortcut ใหม่เมื่อย้ายโฟลเดอร์ครับ

ถ้าต้องการ icon neo ให้เปิด Properties ของ Shortcut → Change Icon แล้วเลือกไฟล์ `rakazo\assets\robot-cats-v1\crd-bot-neo-cat-6f0d37c0.ico` ครับ ส่วน icon ของหน้าต่าง/แท็บและ avatar ภายในแอปต้องติดตั้ง branding ใน web image แยกโดยผู้ดูแล จึงยังไม่เหมือนเครื่องต้นแบบโดยอัตโนมัติครับ

## 7. ทดสอบก่อนส่งมอบ

ทดสอบผ่านหน้าต่างแชตจริงตามลำดับครับ

| ทดสอบ | เกณฑ์ผ่าน |
|---|---|
| ปิดหน้าต่างแล้วเปิดจาก Shortcut | เปิดแอปได้โดยไม่แสดง startup error ครับ |
| ส่ง `สวัสดี แนะนำตัวสั้น ๆ` ให้ neo | ข้อความส่งได้และคำตอบปรากฏในหน้าต่างครับ |
| ส่งคำขอข่าวด้านล่าง | ได้ 3 บทความคนละ URL พร้อมเนื้อหาสรุปและวันที่เผยแพร่ที่ตรวจจากบทความครับ |
| ตรวจการส่งงาน neo → swift → neo | เห็นการส่งงานและคำตอบสุดท้ายในแชต neo ครับ |
| ปิดและเปิดแอปอีกครั้ง | ประวัติยังอยู่และส่งข้อความใหม่ได้ครับ |

ข้อความสำหรับทดสอบครับ

```text
ช่วยค้นข่าว AI ล่าสุดที่สำคัญ 3 เรื่อง โดยค้นเว็บใหม่และเปิดอ่านบทความจริง
พร้อมสรุปสั้น ๆ วันที่เผยแพร่ และลิงก์ต้นทางของแต่ละเรื่องครับ
ถ้าเว็บปฏิเสธให้เปลี่ยนแหล่ง และถ้ายืนยันไม่ครบให้แจ้งจำนวนที่ยืนยันได้จริงครับ
```

วันที่ใน URL หรือ snippet อย่างเดียวไม่ถือเป็นหลักฐานวันเผยแพร่ครับ เมื่อผลไม่ครบให้บันทึกข้อจำกัดตามจริง ไม่ให้คะแนนผ่านเพราะบอทบอกว่าทำสำเร็จครับ

**ข้อจำกัดที่ทราบ:** เครื่องต้นแบบเคยส่งคำขอผ่านหน้าต่างจริงสำเร็จและ backend ทำงานจบ แต่หน้าต่างยังแสดงกำลังทำงานครับ การแสดงคำตอบอัตโนมัติจึงยังต้องตรวจซ้ำบนเครื่องทีมครับ

## แก้ปัญหาเบื้องต้น

| อาการ | ตรวจอย่างไร |
|---|---|
| เปิด GitHub ไม่ได้ | ตรวจสิทธิ์เข้าถึง repository และ branch ครับ |
| WSL หรือ Docker ไม่พร้อม | กลับไปตรวจขั้น 1–3 ใน INSTALL และข้อความ `[FAIL]` ครับ |
| Shortcut เปิดไม่ได้ | รัน `rakazo-start.ps1` จาก PowerShell เพื่ออ่านข้อความผิดพลาด และตรวจว่า path ยังอยู่ครับ |
| เข้าเว็บได้แต่บอทไม่ตอบ | ตรวจการเชื่อมโมเดล สิทธิ์บัญชี และสถานะ worker ครับ |
| swift ส่งกลับ neo ไม่ได้ | ตรวจ neo ID ใน Instructions และการตั้งค่าบอทบนเครื่องนั้นครับ |
| ข่าวบางเว็บ 401/403/429 | ให้ swift เปลี่ยนแหล่ง ไม่เรียก URL ที่ปฏิเสธซ้ำครับ |
| แชตแสดงกำลังทำงานค้าง | ลอง `Ctrl+R` หนึ่งครั้ง ตรวจคำตอบล่าสุดก่อนส่งซ้ำ และแจ้งผู้ดูแลหากเกิดซ้ำครับ |
| ต้องการชุดเหมือนเครื่องต้นแบบทั้งหมด | ต้องเตรียม custom runtime bundle, credentials ของปลายทาง และบริการเสริมแยกครับ ยังไม่มี bundle สำหรับดาวน์โหลดสาธารณะในคู่มือนี้ครับ |

ส่งข้อมูลให้ผู้ดูแล: commit จาก `git log -1 --oneline`, ขั้นตอนที่ติดขัด, เวลาเกิดเหตุ และข้อความ error ที่ปิดข้อมูลลับแล้วครับ
