# Research Report — 4-Stage Workflow

ทำทีละขั้นตามลำดับ แต่ละขั้นต้องผ่าน **Gate** ก่อนไปขั้นถัดไป ถ้าไม่ผ่าน Gate ให้กลับไปทำขั้นนั้นใหม่ หรือแจ้งพี่บุ๋มว่าติดอะไร

## ขั้น 0 — Setup
1. สร้างโฟลเดอร์ `shared/research/<YYYYMMDD>-<slug>/` (slug = ภาษาอังกฤษตัวเล็ก คั่นด้วย `-`)
2. เขียน `STATUS` = `IN_PROGRESS`
3. เขียน `00_brief.md`:

```markdown
# Brief: <ชื่องาน>
- ผู้สั่ง: พี่บุ๋ม | วันที่: YYYY-MM-DD | กำหนดส่ง: YYYY-MM-DD
- คำถามหลัก:
  1. ...
- ขอบเขต: พื้นที่ / ช่วงเวลา / กลุ่มเป้าหมาย
- ใช้ผลเพื่อ: <การตัดสินใจที่จะใช้ผลนี้>
- รูปแบบผลงาน: md / docx / pdf
- สมมติฐานที่ใช้: (ถ้ามี)
- นอกขอบเขต: (สิ่งที่จะไม่ทำ)
```

## ขั้น 1 — ค้นคว้า → `01_sources.md`
1. แตกคำถามหลักเป็นคำถามย่อย แล้วค้นด้วย `web_search` + อ่านหน้าด้วย `web_fetch` (หน้าที่ต้องใช้ JavaScript ให้เปิดด้วย browser ใน computer) ตามลำดับความน่าเชื่อถือ:
   1. หน่วยงานรัฐ / ข้อมูลทางการ (ธปท., สำนักงานสถิติแห่งชาติ, กรมโยธาธิการฯ, REIC, ตลาดหลักทรัพย์ฯ)
   2. รายงานบริษัทจดทะเบียน (56-1 One Report, งบการเงิน), งานวิจัย/วารสารวิชาการ
   3. บริษัทวิจัย/ที่ปรึกษาเอกชน — ระบุว่าเป็นข้อมูลภาคเอกชน
   4. สื่อข่าวที่มีชื่อเสียง — ใช้ยืนยันเหตุการณ์ ไม่ใช้เป็นแหล่งตัวเลขหลัก
   5. บล็อก / โซเชียล / ฟอรัม — **ห้ามใช้เป็นแหล่งหลัก** ใช้เป็นเบาะแสตามหาแหล่งจริงเท่านั้น
   ตัวเลขสำคัญต้องยืนยันได้จาก ≥ 2 แหล่งอิสระ ถ้าได้แหล่งเดียวให้ติดป้าย `[แหล่งเดียว]`
2. ลอง keyword ทั้งภาษาไทยและอังกฤษ
3. บันทึกทุกแหล่งที่**ใช้จริง**:

```markdown
| ID | แหล่ง (ชื่อ + URL) | ประเภท (รัฐ/บจ./วิชาการ/เอกชน/ข่าว) | วันที่ของข้อมูล | วันที่เข้าถึง | ข้อมูลที่ดึงมา (ตัวเลข/ข้อความ ตรงตามต้นฉบับ) | หน้า/ตาราง |
|---|---|---|---|---|---|---|
| S1 | ... | ... | ... | ... | ... | ... |
```

4. ส่วนท้าย: **"ช่องว่างข้อมูล"** — คำถามย่อยไหนที่หาข้อมูลไม่ได้ หรือได้แค่แหล่งเดียว
5. ข้อมูลดิบที่เป็นตาราง ให้เซฟเป็น `data/*.csv` พร้อมคอลัมน์ `source_id`

**Gate 1:** ทุกคำถามหลักมีแหล่งอย่างน้อย 1 แหล่ง หรือมีบันทึกใน "ช่องว่างข้อมูล" · ตัวเลขสำคัญมี ≥ 2 แหล่ง หรือติดป้าย `[แหล่งเดียว]`

## ขั้น 2 — วิเคราะห์ → `02_analysis.md`
1. ทำความสะอาดข้อมูลและคำนวณด้วย Python เก็บสคริปต์ไว้ที่ `analysis/*.py` (ต้องรันซ้ำแล้วได้ผลเดิม)
2. กราฟเก็บไว้ที่ `charts/*.png` ทุกกราฟต้องมีชื่อ หน่วย และแหล่งข้อมูลกำกับ
3. ใน `02_analysis.md` ให้เขียน:
   - วิธีวิเคราะห์ที่ใช้ และเหตุผลที่เลือก
   - ผลลัพธ์ (ตาราง/กราฟ) — ทุกตัวเลขอ้าง `S#` หรือ `analysis/<file>.py`
   - ความผิดปกติของข้อมูล / ข้อมูลที่ขัดกันระหว่างแหล่ง และวิธีจัดการ
   - ข้อจำกัดของการวิเคราะห์

**Gate 2:** รันสคริปต์ใน `analysis/` ใหม่ทั้งหมดแล้วได้ตัวเลขตรงกับใน `02_analysis.md` · ไม่มีตัวเลขที่ไม่มีที่มา

## ขั้น 3 — Insight และสรุป → `03_insights.md`
Insight ≠ สรุปข้อมูลซ้ำ insight ต้องตอบว่า **"แล้วไง / มีผลต่อการตัดสินใจยังไง"**

```markdown
## Insight 1: <ประโยคเดียว ชัด>
- หลักฐาน: [FACT] ... (S1, S3) · [ANALYSIS] ... (analysis/trend.py)
- ความหมายต่อการตัดสินใจ: ...
- ความมั่นใจ: สูง / กลาง / ต่ำ — เพราะ ...
- อะไรจะทำให้ insight นี้ผิด: ...
```

- ไม่เกิน 3–7 insights เรียงตามผลกระทบต่อการตัดสินใจ
- ต้องมีอย่างน้อย 1 ข้อที่เป็น **มุมมองฝ่ายตรงข้าม / ความเสี่ยง** ที่ขัดกับข้อสรุปหลัก

**Gate 3:** ทุก insight ตอบคำถามหลักใน `00_brief.md` ได้อย่างน้อย 1 ข้อ · ไม่มี insight ที่สรุปเกินกว่าหลักฐาน

## ขั้น 4 — รายงาน → `04_report.md` (+ .docx/.pdf ถ้าสั่ง)
โครงสร้างบังคับ:

```markdown
# <ชื่อรายงาน>
วันที่ · ผู้จัดทำ: Research Analyst (AI) · สถานะ: ร่าง — รอตรวจ

## 1. Executive Summary  (≤ 5 bullet ตอบคำถามหลักตรงๆ)
## 2. คำถามและขอบเขต
## 3. Key Findings  (ตาราง/กราฟสำคัญ)
## 4. Insights  (จาก 03 พร้อมระดับความมั่นใจ)
## 5. ข้อดี / ข้อเสีย / ความเสี่ยง
## 6. ข้อเสนอแนะและขั้นตอนถัดไป
## 7. ข้อจำกัดและช่องว่างข้อมูล
## ภาคผนวก: แหล่งอ้างอิง (ตาราง S# จาก 01)
```

- ถ้าสั่ง .docx ให้แปลงด้วย `pandoc` หรือ `python-docx` ส่วน .pdf แปลงจาก .docx หรือ HTML
- Self-check ก่อนส่ง:
  - [ ] ทุกตัวเลขใน Executive Summary ตรงกับใน 02/03
  - [ ] ทุก `S#` ที่อ้างมีอยู่ใน 01 และลิงก์เปิดได้
  - [ ] มีส่วนข้อจำกัด
  - [ ] ไม่มีคำว่า "ประมาณ" ที่ไม่มีที่มาของตัวเลข

**Gate 4:** self-check ผ่านครบ → เขียน `STATUS` = `READY_FOR_REVIEW` → เรียก `message_bot` ถึง "Research Reviewer" (intent: `request`) ข้อความ: `ขอตรวจงาน: shared/research/<โฟลเดอร์>/ รอบที่ N` → แจ้งพี่บุ๋มในแชท: ชื่องาน, path, Executive Summary 3 บรรทัด

## เมื่อถูกตีกลับ (`STATUS=REVISE`)
1. อ่าน `review.md` ทุกข้อ
2. แก้เฉพาะข้อที่ถูกชี้ ถ้าไม่เห็นด้วยกับข้อไหน ให้เขียนเหตุผลพร้อมหลักฐาน (ห้ามเงียบ)
3. เพิ่มส่วนท้าย `04_report.md`: `## การแก้ไขรอบที่ N` → ตาราง | ข้อที่ Reviewer ชี้ | แก้อย่างไร / เหตุผลที่ไม่แก้ |
4. เขียน `STATUS` = `READY_FOR_REVIEW` แล้วเรียก `message_bot` ถึง Reviewer เหมือน Gate 4
