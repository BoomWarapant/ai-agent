# ขั้นตอนทดสอบระบบ Research ใน Rakazo

> v0.1 · 2026-10-04 · ใช้เวลาประมาณ 1.5–2 ชั่วโมง (ส่วนใหญ่เป็นเวลารอบอททำงาน)
> ชื่อปุ่มและเมนูในเอกสารนี้อิงจาก source code ของ Rakazo ล่าสุด ถ้าเวอร์ชันในเครื่องพี่ใช้ชื่อต่างไป ให้ถ่าย screenshot ส่งไอ้ฟู

## กติกาการทดสอบ
- ทำทีละขั้น **ขั้นไหนไม่ผ่าน ให้หยุดแล้วส่งผลให้ไอ้ฟูก่อน** อย่าข้ามไปขั้นต่อไป
- จดผลทุกขั้นลงตาราง "บันทึกผล" ท้ายเอกสาร
- ยังไม่ต้องสร้าง routine ใดๆ ระหว่างทดสอบ

| 1.2 | ตรวจ model ของ Space นี้ใน **Settings** (ถ้า Space ใหม่ไม่ได้รับ model มาอัตโนมัติ ให้เลือก GPT) | มี model พร้อมใช้ |

## T2 — สร้างบอท 2 ตัว (15 นาที)

### 2A — Research Analyst
1. กด **New bot** / **Create new Bot**
2. กรอก:
   - **Name:** `Research Analyst` (ต้องตรงตัวอักษรนี้ เพราะ instructions ใช้ชื่อนี้ส่งข้อความหากัน)
   - **Title:** `นักวิเคราะห์ข้อมูลเชิงลึก`
   - **Description:** เปิด `research-analyst/instructions.md` แล้ว copy **เฉพาะเนื้อหาใต้เส้น `---`** มาวาง
   - **Computer:** เลือก **Team**
3. กด **Create**

| ผ่านเมื่อ |
|---|
| บอทถูกสร้าง และตอบข้อความแรกเองว่าเข้าใจบทบาทตัวเองว่าอะไร — **ต้องพูดถึง: ทำงาน 4 ขั้น, ห้ามแต่งข้อมูล, ส่งงานให้ Research Reviewer ตรวจ** |
| ถ้าวางแล้วเนื้อหาถูกตัด (ช่องรับได้ 4,000 ตัวอักษร): ไฟล์นี้ยาวไม่ถึง ไม่ควรถูกตัด ถ้าถูกตัด → หยุด ส่ง screenshot |

### 2B — Research Reviewer
ทำเหมือน 2A แต่ใช้:
- **Name:** `Research Reviewer` · **Title:** `ผู้ตรวจสอบงานวิจัย`
- **Description:** เนื้อหาใต้เส้น `---` ของ `research-reviewer/instructions.md`
- **Computer:** **Team**

| ผ่านเมื่อ |
|---|
| ข้อความแรกของบอทพูดถึง: **ตรวจอิสระ, ห้ามแก้รายงานเอง, PASS/REVISE/REJECT** |

### 2C — เพิ่ม Skill 2 ตัว
1. เปิดแผงตั้งค่าของบอทตัวใดก็ได้ → ส่วน **Knowledge** → แท็บ **Skills** → **New skill**
2. วางเนื้อหา**ทั้งไฟล์** `research-analyst/skills/research-report/SKILL.md` (รวมส่วน `---` ด้านบนสุดที่มี `name:` และ `description:`) → **Save**
3. ทำซ้ำกับ `research-reviewer/skills/research-review/SKILL.md`

| ผ่านเมื่อ |
|---|
| แท็บ Skills มี `research-report` และ `research-review` และเปิดดูจากแผงของอีกบอทก็เห็นทั้ง 2 ตัว |

## T3 — Smoke Test: บอทเห็นของกันและกันไหม (15 นาที)

> ขั้นนี้สำคัญที่สุด ถ้าไม่ผ่าน ระบบส่งต่องานใช้ไม่ได้

**3.1 ตรวจว่าบอทเห็น skill และ tool** — พิมพ์ในแชท **Research Analyst**:
```
ทดสอบระบบ ยังไม่ต้องทำงานจริง ตอบสั้นๆ:
1) คุณเห็น skill อะไรบ้าง
2) คุณมี tool web_search, web_fetch, shell, write_file และ message_bot ไหม
3) เพื่อนร่วมทีมที่คุณส่งข้อความหาได้มีใครบ้าง
```
✅ ผ่าน: เห็น `research-report`, มี tool ครบ 5 ตัว, เห็น `Research Reviewer` ในรายชื่อเพื่อนร่วมทีม

**3.2 ตรวจโฟลเดอร์ร่วม (Team Computer)** — แชท **Research Analyst**:
```
สร้างไฟล์ shared/research/_smoke/hello.txt เขียนข้อความว่า "smoke test จาก Analyst" แล้วบอก path เต็มที่สร้าง
```
แล้วไปแชท **Research Reviewer**:
```
อ่านไฟล์ shared/research/_smoke/hello.txt แล้วบอกเนื้อหาในไฟล์
```
✅ ผ่าน: Reviewer อ่านเจอข้อความ "smoke test จาก Analyst"
(ตรวจเพิ่มได้: เปิด **Computer** → **Files** ดูว่ามีไฟล์จริง)

**3.3 ตรวจ `message_bot` ปลุกบอทปลายทาง** — แชท **Research Analyst**:
```
ทดสอบระบบ: ใช้ tool message_bot ส่งข้อความถึง "Research Reviewer" intent: fyi
ข้อความ: "ping ทดสอบ ไม่ต้องทำอะไร ไม่ต้องตอบกลับ"
```
แล้วเปิดแชท **Research Reviewer**

✅ ผ่าน: เห็นข้อความ **"Message from Research Analyst"** ในแชท Reviewer
📝 จดไว้: Reviewer **เริ่มทำงานเอง** (ขึ้นสถานะกำลังทำงาน) หรือแค่มีข้อความเข้ามาเฉยๆ — ข้อนี้ชี้ว่าต้องใช้ routine สำรองหรือไม่

## T4 — ทดสอบงานจริงครบวงจร (30–45 นาที)

**4.1 สั่งงาน** — แชท **Research Analyst** (โจทย์เล็ก ข้อมูลหาได้จริง):
```
งานทดสอบ ใช้ skill research-report
คำถามหลัก: ยอดโอนกรรมสิทธิ์ห้องชุด (คอนโดมิเนียม) ในจังหวัดเชียงใหม่ ปีล่าสุดที่มีข้อมูล เทียบกับปีก่อนหน้า เพิ่มหรือลดกี่ % และปัจจัยหลักคืออะไร
ขอบเขต: จังหวัดเชียงใหม่ · 2 ปีล่าสุดที่มีข้อมูล
ใช้ผลเพื่อ: ประกอบการพิจารณาจังหวะเปิดโครงการคอนโดใหม่
รูปแบบ: 04_report.md ไม่เกิน 2 หน้า
ไม่ต้องทวนโจทย์ ทำจนถึงส่งตรวจ
```

**4.2 ระหว่างรอ** เปิด **Computer** → **Files** → `shared/research/` ไล่ดูไฟล์ที่เกิดขึ้น

| # | ตรวจ | ผ่านเมื่อ |
|---|---|---|
| 4.3 | โครงสร้างไฟล์ | มี `00_brief.md`, `01_sources.md`, `02_analysis.md`, `03_insights.md`, `04_report.md`, `STATUS` และโฟลเดอร์ `analysis/` ที่มีไฟล์ `.py` |
| 4.4 | `01_sources.md` | มีตารางแหล่ง S1, S2… มี URL และวันที่ข้อมูล · **พี่สุ่มเปิดลิงก์ 2 อัน ต้องเปิดได้และมีตัวเลขตรงตามที่ระบุ** |
| 4.5 | `04_report.md` | ครบ 7 ส่วน · ตัวเลขใน Executive Summary มี `S#` กำกับ · มีส่วนข้อจำกัด |
| 4.6 | การส่งตรวจ | `STATUS` = `READY_FOR_REVIEW` (หรือเปลี่ยนต่อเป็น `IN_REVIEW`) และในแชท Reviewer มี "Message from Research Analyst" ขอตรวจงาน |
| 4.7 | Reviewer ทำงาน | มี `review.md` ตาม template และ `STATUS` เป็น PASS / REVISE / REJECT |
| 4.8 | ปิดวง | Analyst ได้รับผล ถ้าได้ REVISE → แก้แล้วส่งตรวจใหม่เอง · ถ้าได้ PASS/REJECT → แจ้งพี่ในแชทแล้วหยุด |

**ถ้าข้อ 4.6 หรือ 4.7 ไม่เกิดขึ้นเอง ภายใน 10 นาที** (แปลว่า `message_bot` ไม่ปลุกบอท): ให้พิมพ์ในแชท Reviewer เองว่า `ตรวจงานที่ STATUS = READY_FOR_REVIEW ใน shared/research/` แล้วจดไว้ว่า "ต้องใช้ routine สำรอง"

## T5 — ทดสอบว่า Reviewer จับผิดได้จริง (30 นาที)

> หลักการ: ใช้ Analyst ช่วยฝังข้อผิดลงใน**สำเนา** — Reviewer อยู่คนละแชท ไม่เห็นบทสนทนานี้ จึงยังตรวจได้อย่างอิสระ

**5.1 สร้างสำเนาพร้อมข้อผิด** — แชท **Research Analyst** (เปลี่ยน `<โฟลเดอร์จาก T4>` เป็นชื่อจริง):
```
งานทดสอบระบบตรวจ ห้ามส่ง message_bot หา Reviewer ในงานนี้
1) copy โฟลเดอร์ shared/research/<โฟลเดอร์จาก T4>/ ไปเป็น shared/research/zz-planted-test/ (ลบ review.md ในสำเนาทิ้ง)
2) แก้เฉพาะในสำเนา ฝังข้อผิด 5 จุดนี้:
   ก. ตัวเลขสำคัญตัวแรกใน Executive Summary ให้เพิ่มขึ้น 20%
   ข. ใน 01_sources.md เปลี่ยน URL ของแหล่งหนึ่งให้ชี้ไปหน้าอื่นที่ไม่มีตัวเลขนั้น
   ค. ใน 03_insights.md เพิ่ม insight ใหม่ที่สรุปเกินหลักฐาน และให้ความมั่นใจ "สูง"
   ง. ใน 04_report.md เปลี่ยนป้าย [OPINION] หนึ่งจุดเป็น [FACT]
   จ. ลบส่วน "ข้อจำกัดและช่องว่างข้อมูล" ออกจาก 04_report.md
3) เขียน STATUS ในสำเนา = READY_FOR_REVIEW
4) สรุปให้ผมว่าแก้แต่ละจุดที่ไหน (ไฟล์ + ตำแหน่ง) ผมจะเก็บไว้เป็นเฉลย
```
**จดเฉลยที่ Analyst ตอบไว้** (อย่าส่งให้ Reviewer)

**5.2 สั่งตรวจ** — แชท **Research Reviewer**:
```
ตรวจงาน shared/research/zz-planted-test/ ตาม skill research-review
```

**5.3 เทียบผล** — เปิด `zz-planted-test/review.md` แล้วเทียบกับเฉลย

| ข้อผิด | ระดับที่ควรได้ | จับได้? |
|---|---|---|
| ก. ตัวเลข +20% | CRITICAL | ☐ |
| ข. URL ผิด | CRITICAL | ☐ |
| ค. insight เกินหลักฐาน | MAJOR หรือ CRITICAL | ☐ |
| ง. OPINION → FACT | MAJOR | ☐ |
| จ. ไม่มีส่วนข้อจำกัด | MAJOR | ☐ |

✅ ผ่าน: จับได้ **≥ 4/5** และผลตัดสินต้องเป็น **REVISE** (ห้าม PASS)

> หมายเหตุ: Reviewer จะส่งผลกลับไปหา Analyst ด้วย ถ้า Analyst เริ่มแก้สำเนานี้ก็ไม่เป็นไร ถือเป็นการทดสอบวงตีกลับไปในตัว

## ถ้าเจอปัญหา

| อาการ | น่าจะเป็นเพราะ | ทำอะไร |
|---|---|---|
| บอทบอกว่าไม่เห็น skill | skill อยู่คนละ Space กับบอท | เช็กว่าสร้าง skill ใน Space `Research Lab` |
| Reviewer อ่านไฟล์ของ Analyst ไม่เจอ | บอทตัวใดตัวหนึ่งเลือก Computer เป็น Private | แก้เป็น Team ทั้งคู่ |
| message_bot หาเพื่อนไม่เจอ | ชื่อบอทไม่ตรง หรืออยู่คนละ Space | ชื่อต้องเป็น `Research Analyst` / `Research Reviewer` ตรงตัว |
| Reviewer ไม่ตื่นเองหลังได้ข้อความ | message_bot ไม่ปลุกบอทในเวอร์ชันนี้ | ใช้ routine สำรองใน `routines.md` (ไอ้ฟูจะปรับให้) |
| web_search ใช้ไม่ได้ / ไม่มีผล | เวอร์ชันหรือ config ต่างจาก source ล่าสุด | ส่ง error ให้ไอ้ฟู — ทางเลือกคือให้ค้นผ่าน browser ใน computer |
| บอทคิดเลขเอง ไม่มีไฟล์ใน analysis/ | instructions ไม่ถูกบังคับพอ | จดตัวอย่างไว้ ไอ้ฟูจะปรับ skill |
